# Bolt's Journal - Critical Learnings

## 2026-11-06 - Early-exit on token inequality before inter-token string slicing and predicate checks
**Learning:** In Punakyna's grammar rules, `check_double_word` iterated through every adjacent pair of words in a sentence and performed substring slicing (`sent_text[prev.end:cur.start]`), whitespace `.strip()` calls, and character casing inspections (`isupper()`) before finally checking whether `prev.lower == cur.lower`. Because consecutive words in natural language are almost always distinct (>99% of pairs), performing inter-word string slicing and method calls on every adjacent pair incurred substantial unnecessary allocation and overhead. Moving the equality guard `if prev.lower != cur.lower: continue` to the top of the loop reduced `check_double_word` latency by ~61.7% across multi-paragraph documents (from 151.39ms down to 58.05ms per 100 iterations) with identical diagnostic behavior.
**Action:** In rules verifying token duplication or consecutive relationships, always place identity checks (`prev.lower == cur.lower`) before intermediate string slicing, regex matching, or secondary property checks.

## 2026-11-05 - Eliminate per-token generator allocations and string scans in hot pipeline loops
**Learning:** In Punakyna's spelling and sentence/token processing loop, generator expressions like `any(c.isdigit() for c in w)` and redundant `w.lower()` invocations created hundreds of thousands of ephemeral generator frames and method calls. Replacing `any(c.isdigit() for c in w)` with `not _DIGITS.isdisjoint(w)` reduced digit check latency by ~75% (~4x faster), using pre-calculated `tok.lower` eliminated redundant lowercase copies, and replacing `text.find(s.sentenceText, pos)` with prefix checks (`startswith`) bypassed unnecessary full-string scans over long documents. This reduced multi-paragraph document check latency by ~42.5% (from 24.19ms down to 13.90ms per iteration) without altering token positions or rule outputs.
**Action:** When filtering words or tokens in tight loops, prefer set disjoint checks (`set.isdisjoint`) over generator expressions with `any()`, reuse cached lowercase token attributes, and check contiguous sequence boundaries before falling back to full-string `.find()`.

## 2026-11-05 - Avoid morphological analysis on non-target tokens in narrow grammar rules
**Learning:** In Punakyna, `check_olla_agreement` targets copula agreement with the 3rd person present indicative forms of "olla" (`on` / `ovat`). However, the rule was querying `voikko.analyze()` across C-FFI for *every* adjacent token pair in every sentence. Because `libvoikko.analyze` is relatively expensive and most words are not "on" or "ovat", this accounted for over 84% of all rule-level analysis calls. Fast filtering with an exact set check (`cur.lower not in {'on', 'ovat'}`) before any C-FFI morphological calls cut standalone `check_olla_agreement` latency by ~79.4% (from 0.785s to 0.162s for 5400 checks) with zero behavioral impact.
**Action:** Before invoking expensive morphological analysis (`voikko.analyze`) in grammar rule loops, check whether the target grammatical category is restricted to a small, finite set of surface forms (e.g. specific auxiliaries or copulas) and fast-path/early-exit on string matching.

## 2026-11-03 - Dynamic `type()` generation inside token loops
**Learning:** Creating dynamic types via `type('T', (), {...})()` inside a hot per-sentence token loop incurs massive overhead due to repeated class creation, dictionary allocations, and type construction in Python. In Punakyna, replacing this with a dedicated slotted class (`_PipelineToken` with `__slots__`) dropped long paragraph checking times by ~58% (from ~0.675s down to ~0.278s for 20 runs) and reduced smoke test runtime by ~29%.
**Action:** Always define slotted classes or dataclasses at module level for per-token or per-element processing in pipelines instead of inline anonymous type factories.
